# POTS Tracker v0.1.7: calm gestures, OLED black, Journal Lock, and Apple Health

## Physical iPhone feedback carried forward
- v0.1.6: both swipe directions work, and deletion confirmation is good.
- User requests slightly slower, clearer swipe animation and no gesture overlay on ordinary taps.
- Long press / press-and-hold is no longer desirable because it competes with the swipe. Remove it; do not add it back.
- User requests genuine black dark mode instead of the previous flat gray color.
- User requests optional Face ID or a passcode for Journal privacy.
- User requests permission-based access to existing iPhone Health data (steps and similar), without requiring Apple Watch.

## Implemented
- Swipe rails have a slower 0.34-second settle animation and only reveal actions on deliberate horizontal drags; full flings no longer bypass the action rail. Tapping opens directly, without flashing colored buttons. Long-press menus stay removed.
- True black OLED dark canvas, near-black cards, and brighter teal accents; original approved colorful icon artwork is retained.
- An **optional** Journal Lock setting under More / Settings using LocalAuthentication with Face ID, Touch ID (where available) or the iPhone's existing passcode. Enabling and disabling lock both require successful authentication.
- Journal navigation and editing are gated; locked Journal notes are hidden from Home and grouped History. When unlocked, screens may show them. Going to background or leaving the Journal relocks it.
- Full-history deletion requires unlocking Journal first if Journal Lock is enabled. Prevent accidental omission or deletion of hidden records.
- Journal Lock is a UI access gate, **not separate encryption of the Core Data store**; describe this limitation clearly.
- Optional, read-only Apple Health screen in More showing today's step count, walking/running distance, flights climbed **if accessible**. There is no Apple Watch app, integration, connection, or requirement.
- HealthKit authorization is requested only after the user taps Connect Apple Health; no writes, background access, cloud, account, or automatic import into the app's records.
- If Health has no accessible samples, show a dash instead of fabricating zero; Apple's privacy policy does not tell apps whether read access was denied or no samples exist.
- Adds `NSFaceIDUsageDescription`, `NSHealthShareUsageDescription`, `com.apple.developer.healthkit` entitlement. This **requires compatible signing and an App ID/profile with HealthKit enabled** for actual read access. The GitHub release IPA is unsigned.
- Keep iOS 16 minimum, same app ID, Core Data schema, journal/check-in validation, date→category→record History, all approved art, customization and no premium tiers.
