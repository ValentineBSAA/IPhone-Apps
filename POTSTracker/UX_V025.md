# POTS & Posies v0.2.5 • Home Experience & Backup Usability

## User-approved change request
Based on the physical-iPhone Home screenshot and the v0.2.4 test-build feedback: the old Today card is attractive but duplicates the three tracker shortcuts already on Log and pinned Home modules. Replace Today with an accessible, calmly paced four-page carousel. Backups should be understandable to a nontechnical user. Prefer iCloud Drive as the destination, simplify the primary flow, and leave JSON under Advanced.

## Implemented
- Four-page swipeable **Today / Your week / Daily wellbeing / Coming up** Home carousel using native `TabView`, with page dots, previous/next controls, VoiceOver labels and Reduce Motion support. No auto-advance.
- Today summarizes count/check-in and a single Add Entry action. Week shows actual last-seven-day recorded dates and links to Calendar. Daily wellbeing totals only manually recorded hydration mL, sleep/rest minutes, and medication entry count; never implies that a medication was taken. Coming Up uses optional locally saved reminder schedule, but does not leak user-written reminder names onto Home. Unknown days/measurements remain *Not recorded*.
- Existing Home customization ID `today`, pinned shortcuts, check-in, logged-today status dots, four-tab routing, Face ID Journal, Midnight/Blossom, all 12 icons, and Core Data schema are preserved.
- **Backup & restore** becomes the simple primary UX. The full offline archive remains the established versioned JSON format with stable UUIDs, notes and timestamps. Saving opens the native share sheet, where a user can pick **Save to Files → iCloud Drive** without an app-managed iCloud entitlement. Restoring uses the existing validation/deduplication preview before writing to local Core Data; it will not overwrite existing records. The app never claims a Files save succeeded just because the share sheet opened.
- **iCloud Drive preferred** as the default destination in the UI. Automatic app-managed iCloud Documents backups run **only after separate, explicit informed opt-in**, and only if `FileManager.url(forUbiquityContainerIdentifier: nil)` confirms iCloud is available for the installed signing profile. Signed AltStore builds without a matching entitlement should gracefully show unavailable instead of trying to bypass Apple's rules. No iCloud entitlement is inserted in the unsigned IPA; a future distribution profile with the capability could enable app-managed backups.
- After an opted-in Core Data commit, a snapshot is written through coordinated iCloud storage, verified by parsing the saved JSON and checking the record count, and only **then** marked successful. No empty archive can replace a previously valid one; the most recent seven dated snapshots are kept when supported. Background execution is **not** promised. iOS may still delay cloud synchronization, so local file verification is not verification that Apple's servers received it.
- Backup files contain sensitive health records **without a separate app-managed password**. Journal must be unlocked before enabling cloud backup and before creating a complete manual archive. Automatic backup consent includes subsequent private entries. No automatic uploads happen in default non-opted-in state.
- PDF, CSV, and advanced JSON export remain in a collapsed **Advanced exports** section. No app-specific user account, Apple Health, Apple Watch, ad, or subscription required.

**Source note:** Apple's iCloud Documents capability must be authorized by a matching signing/provisioning profile. See https://developer.apple.com/documentation/xcode/configuring-icloud-services/ and https://developer.apple.com/documentation/uikit/providing-access-to-directories.
