# POTS & Posies v0.2.3 | Bottom-tab root routing and private Journal regression

## Physical iPhone bug report
The user confirmed that v0.2.2 fixed Journal locking and improved the Midnight theme, but found a new navigation issue: after unlocking Journal from Home, switching to Log (or another bottom tab), and then choosing Home, the Home tab could restore its old **Journal navigation destination**, request Face ID again, and require an extra Back action. The user wants the **Home button to always mean Home**, including when returning from other tabs.

## Source-level cause
`DashboardView.swift` used four independent `NavigationStack` instances inside a `TabView`. SwiftUI retains each stack's pushed view while moving between tabs. The old `.onChange(of: selectedTab)` called `JournalAccess.shared.lock()`, but never popped or recreated the old stack. Thus the next selection of Home could show the stale Journal destination.

## Surgical fix
- [x] Keep four bottom tabs, tracker screens, approved Strawberry Blossom and higher-contrast Midnight palettes unchanged.
- [x] Add `TabNavigationRevisions` with independent reset versions for Home, Log, History and More.
- [x] Route tab changes through a controlled tab-selection binding. Reset the target stack **before** selecting it to avoid a one-frame flash of old Journal.
- [x] Attach the matching revision to each `NavigationStack.id`; selecting a different tab opens that tab's root.
- [x] Lock private Journal on tab change, preserving the already-accepted v0.2.2 Face ID policy.
- [x] Route Home's Add Entry and History shortcuts through the same tab selection helper.
- [x] Add automated `TabNavigationRoutingTests` for Home arrivals from Log, History and More, Journal → Log → Home, and repeated tab cycles.
- [x] Preserve exact app bundle identity, Core Data schema, local records, icon and permissions.
- [ ] Complete both iOS builds, existing regression tests and artifact validation before release.
