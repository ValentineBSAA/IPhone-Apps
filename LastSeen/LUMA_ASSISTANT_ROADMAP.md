# LumaOS Assistant — approved feature direction (2026-11-25)
## Scope and delivery
Creator requests a Siri-like original fictional OS assistant with spoken input through the real iPhone microphone and a consistent ElevenLabs-generated voice. Add to roadmap as an approved next implementation milestone; do not interrupt the currently running Build 27 packaging job or silently claim that the existing IPA contains it. Determine inclusion in the final consolidated test release after implementation, voice asset approval, and verification. Preserve existing OS-first, free, offline and spoiler-free requirements.
## Experience
- Working name Luma Assistant, subject to creator approval; original visual identity and voice, no copying Siri branding or voice. Dedicated in-game invocation from home/Control Center, compact animated orb/waveform and accessible transcript; tap to speak, stop, cancel, repeat, type instead. Optional in-game foreground wake phrase only after explicit opt-in and separate QA; no always-on background listening, real system assistant replacement or interception.
- Initial personality: warm, capable, calm, concise and consistent. Natural variations, no needless repetition. Useful simulated phone operations: open apps, navigate to permitted records, check unread count, fictional settings, calendar, timer, package/service state, investigation status and optional contextual hints. Read only currently visible/permitted records; never disclose protected files, undiscovered clues, future chapters, passcodes or anonymous identity. No real device actions, real contacts, calls, messages, locations or account access. Confirm destructive in-game actions and keep ordinary controls available.
- Story-aware responses use explicit local state and authored intent/reply catalog; assistant is part of the fictional OS, not an unrestricted chatbot. Preserve suspense and realism; any unusual responses require private narrative authoring, not random corruption or implied real surveillance. Never present actual microphone behavior as fictional deception. No plot answers in voice files, public filenames, QA or ordinary creator reports.
## Technical plan
- Development-only ElevenLabs TTS generation: approve one original licensed voice and sample lines before larger batches; maintain stable voice ID, model/settings, scripts, clip IDs, pronunciations, versions, rights and hash manifest. Initial suggested target 60–100 short clips across greetings, actions, confirmations, clarification, denied/unavailable, hints, cancellation and neutral recovery; target not committed quota. Export original audio, normalize levels, bundle and verify decodes; no ElevenLabs credentials or API calls at runtime. Captions match clips. Dynamic values use text UI and optionally separately approved local speech fallback; do not promise unlimited bespoke generated audio.
- Use AVAudioEngine and public Speech framework APIs on iOS 16+, check supportsOnDeviceRecognition and set requiresOnDeviceRecognition=true before starting recognition; if unavailable, denied, unsupported language or error, offer typed/quick-action fallback without server recognition. Validate in airplane mode on iPhone 16e and maintain offline functionality. Explicit native microphone/speech permissions requested only when feature invoked, accurate purpose strings, visible listening state, stop on cancel, background, interruption, lock/reboot and playback; no raw audio retention, no recording upload, no persistent transcripts of user speech by default. No continuous microphone use while browsing. Local deterministic intent resolver with bounded fuzzy synonyms, clarification and shared app/gate checks. Never interpret guessed protected data as authorization.
- Audio session coordination: pause listening during spoken response, avoid assistant hearing itself, respect sound/haptic preferences, interrupt/cancel cleanly and restore prior audio state. Include text equivalents, VoiceOver, Dynamic Type and reduced-motion options. 
## Acceptance
- Unit tests for intent mapping, unknown utterances, spoiler/security gates, save and state isolation, correct actions, permission/unavailable fallback, clip ID/manifest validation and no network dependencies. UI tests for invocation, listening state, typed alternative, close/reopen, cancel, protected action denial and audio interruption; physical QA actual microphone/permissions, airplane mode, speech recognition quality, speaker/headphones, repeated requests and background behavior. No release claim until applicable tests pass.
