# Relay — modern package manager redesign
Creator feedback, November 25, 2026: the existing jailbreak package manager feels outdated. Approved direction: replace the legacy list-heavy presentation with a polished original LumaOS-native package manager. Preserve the currently running Build 27 corrective CI; no runtime redesign in this documentation revision.
## Experience and visual direction
- Retain Relay name, approved Relay artwork, fictional sources and original LumaOS terminology. Use a consistent contemporary visual system with readable hierarchy, rounded cards, restrained gradients, adaptive light/dark palette, original icons, responsive transitions and generous touch targets; no imitation of a specific real package manager or real network access. Fit iPhone 16e, iOS 16 minimum; respect safe areas, VoiceOver, Dynamic Type, reduced motion, and existing in-game home/exit controls.
- Discover landing: branded header, searchable catalog, featured earned packages, recently certified packages, category filters (themes, tweaks, utilities), and clear installed/update/queue counts. Hide undiscovered packages and spoiler-sensitive descriptions; no fake counts or decorative controls. Use existing local artwork; request creator approval for any additional needed package artwork and preview assets.
- Retain full navigation: Discover, Sources, Updates/Activity, Installed, Search; choose final labels consistently with in-world terminology. Modern compact cards with real icon, title, version, source, summary and actionable status. Search/filter/sort by visible package data; installed and queued state consistently reflected across views; useful empty states, no hidden future entries.
- Package detail: hero artwork, version, description, category, compatibility with fictional OS, source, real available preview assets, change history if authored, requirements for visible packages, clearly labeled free Install/Update/Remove actions. No invented ratings/download statistics. Package access remains earned through Recovery Circuit and sequential certifications, not merely UI visibility.
- Persistent visible queue affordance; review install/upgrade/remove changes, remove individual entries, clear/cancel, conflict/essential protection, explicit confirmation. Show meaningful actual simulated transaction phases and progress, optional expandable terminal log and animation skip, visible completion/error and restart requirement. Never report success until validated commit finishes; cancellation must leave installed state intact. Preserve Build 27's corrected common-mode foreground timing, once-only completion, and LumaShell respring/user reboot.
- Sources remain bundled, offline and recoverable. Keep refresh/restore/add behavior and local source counts. Installed view exposes package status, versions, pending updates and eligible removal, core/essential protection and safe mode. Activity lists actual transaction history and earned notifications. Modern service certification interface, optional plain-language guidance without revealing answers, clear route to installed utilities; earned app shortcuts where appropriate, with existing gate enforcement and state preserved.
## Acceptance / migration
- Reuse RelayCatalog/RelayPlan and existing installed IDs, version map, source keys, flags, settings and history; no reset or duplicate installation. Avoid unnecessary rewrite of validated transaction engine. Preserve package IDs, essential package protections, stale-plan rejection, all story gates, current utility behavior and all prior build functionality.
- Extend existing unit and end-to-end coverage for filters, package detail, queue edits and deduplication, single and multi-package install/upgrade/remove, cancellation, invalid/stale plans, foreground interruptions, respring, userspace reboot, safe mode, unlock gates, old save migration, persistence after relaunch and checkpoint restore. Validate all supported layouts, real content/asset integrity, accessibility, offline behavior and physical iPhone 16e QA. Do not mark finished before CI and verification; no story spoilers in public status.

## Approved source discovery and repository ecosystem — November 25, 2026
Creator explicitly wants players to find and add sources as a meaningful part of the fictional jailbreak experience. Supersedes any earlier assumption that all repositories are always enabled. Build 27 currently bundles Patchline Core, Afterglow Studio and Nightshift Utilities, and recoveredSources unions every source into enabled state. Its Add Source list therefore normally has no candidates. Preserve those three baseline sources for migrated games and introduce a distinct discoverable optional repository tier; never auto-enable newly added optional sources. Keep the essential core protected. Separate baseline required source IDs from the complete local catalog, discovered source IDs and enabled source IDs. Do not silently re-enable deliberately disabled optional repositories on refresh or relaunch.
- Author additional original fictional repositories with distinct owners/brands, icon art, curated package collections, plausible descriptions, version/index metadata and non-routable .example addresses. Initial planning target 5–8 optional sources (not a fixed quota); choose actual names, package assignments, discovery placements and story associations privately, preserving continuity and existing package IDs. Include meaningful cosmetic, utility and system-customization packages, with actual implemented functionality and no dead controls. Never promise unsupported packages. No real jailbreak repository URLs, executable downloads, device modifications or internet dependencies.
- Discovery should occur naturally through permitted in-world browser pages, community posts, messages, documentation, and other legitimately accessible records. Some sources may be earned through service certifications or optional exploration; no mandatory blind guessing, timer grinding or external internet searches. Provide optional spoiler-safe guidance, not a catalog of future source names. No future source names, package contents, locked clues, exact discovery routes or hidden counts in UI, search, debug export, public QA or creator summaries. Do not change the private story without respecting established canon.
- Sources screen: installed/added sources with icon, author, address, available package count, index state, last refresh, enabled status, source detail and visible package list. Add Source accepts manually typed or pasted fictional address, plus a local in-world record action to copy/add a legitimately discovered address; validate canonical local catalog match AND earned discovery authorization, normalize allowed scheme/trailing slash/case where appropriate, handle duplicates, typos, unknown/locked addresses with neutral errors, and show preview + explicit confirmation. Never actually contact the typed URL. Refresh and restore only bundled permitted indexes; no hidden metadata leaks. Support disable/remove for optional sources, preserving installed packages and allowing safe removal of orphaned packages; updates/reinstalls require available enabled source plus package gate. Keep protected core and already installed packages safe.
- Persist discovery and enabled-source states across relaunch and checkpoints; migrate old builds without losing sources, installations, versions, history, earned flags or existing access. Preserve source authorization during queue validation and again at commit; prevent stale plans and direct address guessing from bypassing progression. Reconcile source removals/restores with package availability and safe mode. Integrate existing local notifications, statistics (discovered/added counts only), and future Luma Assistant commands without disclosure of hidden sources.
- Test core recovery versus optional disable/remove, legitimate discovery and add, unknown/duplicate/locked address handling, no network, refresh, package visibility/search/queue/commit gates, optional-source update/remove/re-add, migration, relaunch, checkpoint restoration, installed-package preservation, cancellation/respring, accessibility and actual iPhone 16e offline use. End-to-end simulator test must discover/add a permitted test source and install one eligible package, with no release-only bypass. Keep current Relay correction CI intact; feature is OPEN until implemented and verified.
